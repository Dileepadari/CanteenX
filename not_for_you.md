## The seed created no orders

The biggest gap found during the documentation pass. `scripts/seed.py` built canteens, menus, promotions and users, and then stopped. Zero orders.

That meant a freshly seeded install showed an empty state on **every** screen that matters: the student order list, the vendor kitchen queue, the vendor dashboard, and the admin platform overview. All the revenue figures were zero and all the charts were flat. The app looked broken rather than new.

The seed now places one order in every status through `cart_service` and `order_service` rather than inserting rows, so stock reservations, customization pricing, payment settlement and the status-history rows are produced exactly as they are for a live order.

Four things had to be worked out to make that go through, each of which is a real rule of the domain:

- **Menu items have required option groups**, so an order cannot be placed without choosing a Size. `_default_customizations` takes the first option of each required group, deterministically, so a re-seed produces the same basket and the same totals.
- **An order must be paid before it can be completed.** Wallet is the only method that settles without a gateway round trip, so the seeded orders pay by wallet.
- **The seeded wallet balance covers about two orders, not six.** A demo top-up now precedes the orders, which also gives the wallet screen a real transaction history instead of a single opening balance.
- **Paying moves an order straight to confirmed.** The status walk starts from wherever payment left it rather than from pending, and the pending and cancelled orders are deliberately left unpaid, because otherwise there would be no genuinely pending order to look at.

## Screenshots

- Captured against a local stack: Postgres from compose on 55432, the API run natively on **8001** and Vite on **8081**. Port 8000 was already taken by the TourismToolKit stack running on this machine, and 8000 answering `/health` from a different app is a confusing five minutes if you do not check what is listening.
- Access tokens are short-lived, so a capture session that pauses for a few minutes silently loses the session and starts screenshotting the sign-in page. Re-authenticate immediately before a run of protected screens.
- Zoom regions are in screenshot pixels, not CSS pixels, and the scale differs between browser windows (0.8078 here, 0.8118 in an earlier session). It has to be re-measured per session: capture one full screenshot, divide its width by `window.innerWidth`.
- Mobile captures need a longer settle than desktop. At 4.5s the menu and orders pages were caught mid-fade and came out dimmed; 8s is clean.
- Screenshots were converted from PNG to JPEG at quality 82, which took the directory from 18 MB to 1.3 MB with no visible loss at this size.

### Canteens read "Closed" at capture time

The seed opens canteens 08:00 to 21:00 and the captures were taken at about 03:00 local, so every card correctly showed Closed. Rather than falsify the seed, the live database's hours were widened for the capture session only; `scripts/seed.py` still ships the realistic window.

A first attempt widened the seeded hours to 07:00-23:00 on the assumption the clock was near 21:00 UTC. It was not: local time was 02:58 IST, so that change fixed nothing and made the seed data less realistic. Reverted.

## Local notes

### `app/core/security.py`

- One shared argon2 hasher. The previous build constructed a passlib `CryptContext` in four separate modules, pinned to the passlib 1.7.4 / bcrypt 4.0.1 pair that raises `AttributeError: module 'bcrypt' has no attribute '__about__'`.
- `verify_password` returns False rather than raising for a null hash, because CAS-provisioned accounts have none and the old code turned "SSO user tries the password form" into a 500.
- Realtime tickets live 60 seconds. They are fetched immediately before the WebSocket connects, so they only have to survive one handshake.

### `app/domain/pricing.py`

- `hash_customizations` sorts both keys and values, so `{"size":["l"],"add":["a","b"]}` and `{"add":["b","a"],"size":["l"]}` are the same cart line. The old code compared raw dicts and produced duplicate rows from option order alone.

### `app/api/graphql/permissions.py`

- Policies raise rather than returning False, so the error formatter can attach a machine-readable code the client can branch on: refresh the token, or show a forbidden screen. Returning False gives a generic denial and a null field.

### `supabase/config.toml`

- Generated by the Supabase CLI. Two em dashes in its upstream comments were replaced with hyphens for consistency with the house rule; a CLI regeneration will bring them back, and that is not worth guarding against.

### CI runs mypy but ignores the result

The `Types` step is `mypy app --ignore-missing-imports --no-strict-optional` with
`continue-on-error: true`, and `mypy` currently reports 53 errors across 12 files. The step is
therefore decorative: it can never fail the build. Making it blocking is a real piece of work,
not a config change, so it is recorded here rather than quietly flipped.

## Open threads
